Executive decision

No complete OSS engine exists.

The correct reuse strategy is compositional: adopt proven components at their architectural layer and keep planning policy, tax orchestration and the deterministic result contract under direct control.

Recommendation

Use reusable math and data substrates. Own the planning engine.

Tax policy, tax-lot bookkeeping and correlated return generation have credible open implementations. The core planning sequence—especially the waterfall, withdrawal gross-up and cross-scenario determinism—does not.

Target architecture

Composable boundaries, deterministic core.

Libraries should serve beneath a versioned domain boundary. No third-party package should decide the household policy sequence, path success or random-number reuse contract.

Non-negotiable build work

Gaps that cannot be delegated to OSS.

These are not small adapter tasks. They are the engine’s differentiators and must be versioned, tested and owned as first-party policy.

Surplus waterfall

NO QUALIFYING IMPLEMENTATION

Encode reserve → employer match → goals/529 → tax-advantaged → brokerage, then one controlled TAXCALC rerun.

Deficit gross-up bisection

NO QUALIFYING IMPLEMENTATION

Implement the specified liquidation sequence and a monotonic solver with a one-cent result tolerance and 100-iteration hard failure.

529 lifecycle / state policy

NO MATURE VERIFIED COMPONENT

Keep limits, deductions, qualified distributions, rollovers and ownership in versioned policy data and tests.

Scenario-level CRN

NO FULL PLANNER FIT

Persist immutable market tapes with seed, RNG version, calibration hash and asset order; never draw inside branch-dependent policy.

Boolean path success

NO COMPLETE IMPLEMENTATION

Success must combine no essential/debt/goal shortfall, legacy target attainment and no calculation errors—not merely “balance not depleted.”

WASM latency contract

NO MEASURED EVIDENCE

Benchmark the 190 ms p95 drag budget, 250-path preview and cancellable 1k–5k background run on target hardware.

Invariants & golden results

NO COMPLETE CONTRACT

Validate per-year/path cash conservation, balance behavior, net worth, dead-owner checks, finite values and canonical PlanResult JSON.

Unified tax orchestration

NO FULL PLANNER

Own the ordering between FICA/SE, state/SALT, federal ordinary income, capital gains/NIIT and RMDs.

Research standard

Strict evidence, not keyword matching.

Metrics are time-stamped snapshots, and a README claim was never enough on its own for technical feature placement.

What “Verified” means here

Each retained repository page was opened live. GitHub metadata was checked for stars, forks, archive/fork state, license, contributors, latest commit and release. The README/source tree and relevant implementation or test files were inspected. External full test suites were not executed, and no financial-policy correctness certification is implied.

  • General tools required at least 300 stars; niche components required at least 100.
  • Latest commit had to fall within the prior 12 months of collection.
  • Archived projects, forks, tutorial repositories and no-code entries were excluded.
  • Community sources were used only to discover candidates, never as proof of correctness.
  • License exceptions and below-threshold references are visible rather than silently promoted.
